FLG-024 — Two GitHub Pages deploy paths ran in parallel; the legacy one failed behind the working one (found 2026-11-20, session T-39). After the PR #27 merge, workflow run 44686774699 (“pages build and deployment”, the legacy branch builder) failed at its deploy step, while the repository’s own Deploy GitHub Pages workflow (run 44686775327) succeeded on the same SHA and the live site served the current content (front page fetched and verified after the merge). Cause: the Pages build type was set to legacy (branch main, path /), so a legacy builder raced the artifact deployment on every push; the authoritative artifact deploy is what actually ships the site. Fix attempted: PATCH /repos/…/pages {"build_type":"workflow"} returned HTTP 404 — the automation token lacks the Administration permission Pages settings require. Manual remedy (owner, one click): repository Settings → Pages → Build and deployment → Source: GitHub Actions. Until then, a red “pages build and deployment” run may appear after each merge; judge deploys by the Deploy GitHub Pages workflow and the live URL, which is what this site has always deployed through.

Basis: GitHub Docs — What is GitHub Pages? (S05) — Pages deployment sources; judge deploys by the workflow and live URL
