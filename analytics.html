Trust · Analytics & privacy

Analytics and email: current status

Kitchen Counter · Status checked 2026-11-20 · No server-side collection is enabled

In plain language: the site currently keeps a few event counts in your browser's local storage. It does not send analytics events to a server, so there are no site-wide click or readership totals. There is no working email signup.

What the page script counts locally

  • page_view — a page load in this browser.
  • outbound_click — activation of a supplied product link; the local counter does not identify a person.
  • article_read — reaching the halfway point of an article in this browser.
  • chooser_complete — completing the three-question chooser. Changing an answer after completion is counted as a new completed set of choices.
  • reader_signup — reserved for an email provider's confirmed signup response. No signup form or email provider is connected, so this event is not currently emitted.

What is not configured

  • No self-hosted analytics endpoint: the endpoint setting in assets/app.js is blank. GitHub Pages serves static files and does not receive the site's event POSTs.
  • No aggregate event data: localStorage counts stay in the visitor's browser. They are not uploaded or shared with Kitchen Counter.
  • No email collection: the earlier demo form has been removed so it cannot suggest an address was saved when it was not. For new articles, use the RSS feed in a feed reader.

Local storage and control

The event counters are stored by this browser for this site and persist until browser storage is cleared. They are not cookies and do not contain an email address, name, account, or cross-site identifier. You can clear them using your browser's site-data controls. The small counter shown in the footer is a local-device counter, not a visitor total.

Why there is no server endpoint

A deployable, privacy-preserving collector ships as code at analytics/collector/worker.js (with deployment steps in its README). It is not deployed: no host, retention period, or privacy notice has been selected, so the endpoint setting in assets/app.js stays blank and nothing is transmitted. A build gate fails if that setting is filled in without being named here.

Two rules shape this. The Operating Agreement requires an accurate disclosure of any cookie, pixel or other tracking technology in use, plus the choices available to a visitor (S01). And Program Policies §4 requires that any email carrying a Special Link is opted into (S02). Both would have to be satisfied before a single event left this browser, and neither is configured.

Basis: Operating Agreement (S01) · Program Policies §4, Promotional Limitations (S02)

Before any server collection is enabled

A hosting endpoint, origin policy, retention period, access controls, and privacy notice must be selected and tested. The current static site cannot implement that service by itself. No analytics endpoint, email provider, or Search Console property has been configured in this repository; the Amazon account's assignment and eligibility remain unverified. Until those prerequisites are deliberately configured, this page's local-only description remains the source of truth.
